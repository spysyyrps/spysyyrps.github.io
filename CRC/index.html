循环冗余检验码(CRC)

本文最后更新于：2026年7月31日 上午

一、前言

本文将会介绍检错中常用的 循环冗余检验码（Cyclic redundancy check，CRC） 除了CRC基础流程，本文将会探讨以下几个问题：

  • CRC背后涉及哪些数学原理？
  • 为什么 “加” 余数可以 “被整除”？
  • 为什么说任何长度为 n 的突发错误都可以被 多项式次数 ≥ n 且 常数项 （x0） 的系数非零 CRC 多项式检测?
  • 什么是 本原多项式（primitive polynomial） ？为什么同等次数下，本原多项式检验二比特错误能力更强？
  • 为什么生成多项式基本都有一个 +1 项？
  • 为什么有些生成多项式喜欢采用 $(x+1)\times本原多项式$ ？

如果有误欢迎探讨指正

二、CRC 流程

发送方与接收方事先约定好一个位长为 r + 1 的生成多项式 G（最高次为 r，对应 r + 1 位二进制系数）。由此得到的校验码（FCS，Frame Check Sequence）长度为 r 位。

约定：下文示例取 G = 1101（即 x3 + x2 + 1，r = 3），待发送数据 M = 101001。

发送方：

发送方的目标是计算出 r 位的校验码 R，并拼接到数据 M 之后发出。步骤如下：

1. 补 0：在数据 M 末尾追加 r 个 0，得到 M′ = M ⋅ 2r（相当于左移 r 位，给校验码腾出位置）。

  • 示例：M = 101001，r = 3 → M′ = 101001 000

2. 模 2 除法求余：用 M′ 除以 G，得到余数 R（不足 r 位时前面补 0；商被丢弃，只保留余数）。

模 2 除法规则——每一步看当前段最高位：

  • 为 1：商 1，将当前段与 G 做异或；
  • 为 0：商 0，将当前段与等长的 0 异或（即原样保留），再落下一位继续。

对 M′ = 101001000 除以 G = 1101：

3. 拼接发送：把余数 R 拼到原数据 M 之后（替换掉第 1 步补的 r 个 0），构成发送帧 T = M∥R。

  • 示例：T = 101001∥001 = 101001001

接收方：

接收方只需做一件事：用收到的帧除以同一个 G，检查余数是否为 0。

1. 模 2 除法求余：对收到的帧 T′（含校验码，不补 0）除以约定好的 G。

假设无误收到 T′ = 101001001，除以 G = 1101：

2. 判定：

  • 余数为 0 → 认为帧未出错，接收；
  • 余数非 0 → 检测到差错，丢弃并请求重传。

若传输中发生比特翻转，T′ 通常不再是 G 的倍数，余数非 0，差错即被检出。

三、GF(2)上的多项式

CRC的运算实际上是基于GF(2)的运算 将视角从 实数域 转向 伽罗瓦域 (GF(2)) 能帮助你更好理解CRC 此节可能帮助你更好理解

  • 加法即减法
  • 模二除法
  • 拼接余数实现整除

3.1 伽罗瓦域 GF(2)

GF(2) 下的世界只有 0 和 1 。 为了避免计算结果超出 0和1 ，会在计算后进行 模2 操作保证输出结果只会出现 0或1 在此操作下，加法等同于 异或运算 ，乘法等同于 与运算 观察表格发现，在GF(2)中， 一个数的相反数就是其本身 考虑 GF(2) 下的减法，a − b 等价于 a + (−b) ，即加上另一个数的相反数，而由于GF(2)中相反数等于自身，因此 a − b 等价于 a + b 。这就是为什么 “加法” 即 “减法”

3.2 模二除法

我们可以借助 长除法 理解 模二除法 下图是 1111000 与 1101 之间的模二除法 GF(2)下的长除法与平时接触的基本一致：前端对齐，试商（只有0或者1因此更加简单），作差求余，降位后移 与我们平时接触的最大差别就是在每一次的 作差求余 上 在理解 加法即减法 后我们就可以很好理解上图中展示的模二除法过程 作差 等同于 求和 ，而GF(2)下的 求和 等同于 异或 ，因此，长除法中的 作差求余 结果等同于 按位异或

3.4 探讨

a. 为什么CRC要末端补n个0

当CRC的生成多项式（即除数二进制串对应的多项式）最高次为n时，会在数据末尾补n个0。这些冗余位是单独用于存放余数，这样能在不破坏原始数据的前提下加上余数。而 n次生成多项式对应的二进制串长度为n+1，在GF(2)下，余数长度一定小于除数长度 ，因此，n位冗余足以存放n次生成多项式对应的各种余数可能。

b. 为什么加上余数接收方可以整除

初见CRC很有可能会对被除数加上余数，反而会使得结果可以整除感到困惑。想要整除，不应该是将被除数减去余数吗？ 那是因为CRC是基于GF(2)，而不是我们常用的实数域。 从前文我们可以了解，在GF(2)中，加法就是减法 ，所以加上余数实际上就是减去余数

四、生成多项式

生成多项式可以随意设计吗？ 什么是本原多项式，为什么说它具备最好的双比特检错能力？ 为什么几乎所有生成多项式都有一个 +1 项？ 为什么说生成多项式具有 (x+1) 因式就可以检查出所有错误比特数为奇数的情况？ … 接下来本节将会探讨与生成多项式相关的一些问题

4.1 背景

我们先补充一些定义和细节，方便后续内容理解

4.1.1 错误码E(x)

CRC主要是用于检测数据传输过程中，由于各种干扰或不稳定导致的 比特位跳变（1->0,0->1） 假设传输内容为 M(x) ，发生错误的过程可以描述为： M′(X) = M(X) + E(X) 其中 E(x) 中系数不为0的项的位置（相应二进制串为1的位置）即对应着发生错误跳变的比特位 而当 E(x) 能够被CRC的 生成多项式G(x) 整除时，M‘(x) 也就能被 G(x) 整除，这意味着接收方认为没有发生错误，将会产生漏检！ 因此，错误能否被顺利检出，重点在于 E(x) 能否被 G(x) 整除

4.1.2 本原多项式(primitive polynomial)

主要介绍 GF(2) 下的本原多项式内容

阶的定义： 给定一个多项式 G(x) ,对于形如 $F(x)=x^k+1,k\in正整数集$ 的多项式。对于最小的 k 能使得F(x)可以被G(x)整除，那么称G(x)的阶为k。 本原多项式具有的性质：

  • 不可约，不具有除本身与1外的子因式
  • 对于n次的本原多项式，其阶为同次下的最大值：2n − 1
  • 除一二次外，本原多项式并非唯一，一般而言次数越高，该次数下的本原多项式越多

考虑篇幅与内容，本原多项式的更多具体内容与证明不在此说明了

4.2 单比特错误检测

任何至少包含两个非零系数项的多项式，都可以检测所有单比特错误 如前文所述，能否检测错误，主要看 E(x) 能否被 G(x) 整除 单比特错误情况下，E(x) 为形如 $x^k,k\in非负整数集$ 的多项式，只具备 xi 形式的因式，显然无法被至少包含两个非零系数项的多项式整除

4.3 双比特错误检测

此处仅关注多项生成多项式，不考虑 G(x) = xk, k ∈ ℤ ≥ 0 的情况，此情况下显然有极大概率漏检

当两个比特错误之间的距离小于生成多项式的阶数时，所有此类双比特错误都将被检测到

维基百科对此的描述为 All two bit errors separated by a distance less than the order of the primitive polynomial which is a factor of the generator polynomial will be detected. 个人认为有点不够准确全面

双比特错误可以描述如下： E(x) = xm + xn = xn (xm − n + 1),  m > n ≥ 0 xn 部分无法被多项G(x)整除，因此重点考虑 xm − n + 1 , m-n 正好描述两个错误比特间的距离 前文关于阶的介绍可知，假设G(x)的阶为k，即G(x)可以整除 xk + 1 而一定不能整除 xi + 1, i ∈ {1, 2, …, k − 1} 因此当错误比特距离 m-n 小于阶时，E(x)一定无法被G(x)整除，错误一定会被检测到 而 本原多项式 具有同次下最高的阶，因而具备同次下最好的双比特检错能力，相同冗余位数下最优的双比特检错能力

4.4 奇数个错误比特

本原多项式的确具备优秀的双比特检错能力，但是许多CRC生成多项式都不会直接采用本原多项式，而是倾向于 (x + 1)(本原多项式) 而这么做的理由是： 所有奇数个比特错误都能被含有 x+1 因子的多项式检测 加上 x+1 因子，虽然损失一半左右的双比特检错能力，但是获得对所有奇数个比特的检错能力 假设 G(x) = (x + 1)H(x) , G(1) = 0 ，x = 1 是多项式的一个根（注意是在GF(2)下） 而当有奇数个错误比特时，E(x)存在奇数个项，E(1) 为奇数个1相加，必然等于1 所以 x = 1 一定不是 E(x) 的根，E(x) 一定不具备 x+1 的因子，E(x) 一定无法被具有 x+1 因子的 G(x) 整除，错误一定会被检出

4.5 错误长度与G(x)次数

错误长度： 第一个错误比特与最后一个错误比特的距离长度 若次数为n的 G(x) 具备 x0 项，那么所有错误长度小于等于 n 的突发错误都能被检测 因为 G(x) 具备 x0 项，所以它没有 x 因子（从二进制串理解即末端没有0） 假设错误长度不超过 n 的 E(x) E(x) = xiB(x) 其中 B(x) 为次数不超过 n-1 次的无 x 因子的多项式 考虑 E(x) 能否被 G(x) 整除，由于 G(x) 不具备 x 因子， xi 与 G(x) 互质，所以只要考虑 B(x) 能否被 G(x) 整除 而 G(x) 次数为 n ，高于 B(x) ，高次多项式不可能是低次多项式的因式，所以 B(x) 一定不能被 G(x) 整除 但是， 如果 G(x) 具备 x 因子，那么就会由于与 E(x) 中的 xi 因子相约分，发生降次，导致考虑 B(x) 时次数小于 n，可能发生整除

4.6 X0 项

最后探讨为什么很多生成表达式 G(x) 都会携带 x0 项，即 +1 项 简而言之，去除生成多项式对应二进制串末尾的0，并不会影响检错能力，反而可以减少冗余 对于一个没有 x0 项的生成多项式，必然可以表达为 G(x) = xkD(x), k ∈ ℤ+ D(0) = 1 从前文可知，G(x) 相较于 D(x) 在检错能力在 单比特，双比特，奇数个错误比特 上并没有提升 但是 G(x) 相较于 D(x) 也并非完全没有提升 例如错误码 10102 ，101002 可以检出该错误，但是 1012 会漏检 G(x) 可以额外检查出 发生在传输内容二进制串尾端，长度不超过 G(x) 次数的区域的错误 这是好事…吗？ 其实，回看第二节CRC的流程我们可以发现，G(x) 能额外检出的区域正好是 冗余位 ，但是我们真正关心的是 数据位 。添加额外的0，需要更多的冗余位后，获得的提升不过是可以额外查出一些发生在无关紧要地方的错误。 因此，使用 G(x) 完全不如 D(x) 划算
